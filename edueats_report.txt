1. Problem Statement and Motivation 
Students in long online classes lose focus due to tiredness, stress, and poor nutrition and 
posture habits, and existing educational systems do not account for these factors - affecting 
both students (lower focus, worse habits) and parents, who have no visibility into mood, 
posture, or food intake during a class. EduEats addresses this by detecting student mood from 
webcam images, mapping that mood to nutrient needs, recommending real food from a verified 
nutrition dataset, and monitoring posture during study sessions - full background in the original 
proposal. 
2. Aim and Objectives 
Aim: to build a system that detects a student's mood and posture from webcam images in real 
time and recommends appropriate food and hydration using real nutrition data, to help students 
stay focused and healthy during online classes. 
Objectives: 
• Detect student mood from webcam images in real time using a CNN trained on FER -
2013. Measured by test-set accuracy and F1 score. 
• Recommend food and hydration matched to the detected mood, using a rule engine 
over a real, source-verified nutrition dataset. Measured by whether every mood returns a 
non-empty, nutrient-justified food list. 
• Monitor student posture continuously during a session and flag poor posture. 
Measured by live posture status shown during a real session. 
• Store all student mood, food, and posture data in a structured relational database. 
Measured by every real app action producing a verifiable database row. 
• Notify parents of mood, food, and posture concerns through a privacy -appropriate 
channel. Measured by a working parent -facing alert reaching a parent account - not yet 
met, see Section 6. 
What changed since the proposal: the mood categories implemented are the 7 rea l FER-2013 
emotion classes (angry, disgust, fear, happy, neutral, sad, surprise), not states like "sleepy" 
used as an example in planning documents - FER-2013 is a facial emotion dataset, not a 
drowsiness detector, so a CNN trained on it cannot output a mood it was never trained to 
classify. Also, the parent notification objective is being redesigned (Section 6) after a project 
review raised privacy concerns with the originally planned approach. 
 
3. Methodology and System Design 
3.1 Architecture and data flow 
EduEats has a React.js front end, a Node.js and Express.js back end with REST APIs, a 
MySQL database, and a Python machine learning layer (a CNN trained on FER -2013) feeding 
a rule-based nutrient engine (Figure 1). 
1. A student starts a study session in the browser; the webcam captures a frame and sends 
it to the backend with the student and session ID. 
2. The backend runs the CNN (FER -2013) as a Python subprocess on that frame, which 
predicts one of 7 real moods (angry, disgust, fear, happy, neutral, sad, surprise).

3. The rule engine maps the predicted mood to nutrient requirements (for example, high 
water, adequate vitamin B) and filters the real 93 -food USDA nutrition dataset against 
each nutrient's dataset median as a high/low cutoff. 
4. The backend saves the mood and the matched foods to MySQL; the matched foods are 
shown on the student dashboard. The same webcam feed is independently analysed in 
the browser with MediaPipe Pose for posture, and posture status is saved and shown the 
same way.

Training approach: the CNN is trained with Adam (learning_rate=0.0001), EarlyStopping 
(patience=10), up to 100 epochs, and evaluated only on the untouched FER-2013 test set, never 
on training data. The rule engine is not trained - its nutrient thresholds are each nutrient's real 
dataset median, and each mood's rule is backed by its own separately verified research citation 
(Section 9). 
Why a CNN plus a separate rule engine, not two learned models: no labelled dataset exists that 
maps "mood to the correct food", so that step cannot be learned the same way mood detection

6. Remaining Work and Plan to Complete the Full System (with a Gantt Chart) 
The items below also respond to feedback from the mid -progress presentation panel: 
multilingual food names and pricing, the parent food -restriction feature, and the shift to a 
dedicated mobile app for the parent side. 
• Add Tamil, Sinhala, and price columns to the nutrition dataset (re -run/extend the existing 
real-source build script, not hand-typed values). 
• Build a parent food-restriction list: parents mark foods their child must not eat, and the rule 
engine filters recommendations against that list. 
• Redesign the parent alert channel away from Firebase Cloud Messaging with a collected 
phone number, after a privacy review flagged it. 
• Decide and implement a privacy -appropriate approach to the mood -detection photo itself 
(e.g. never persisting the frame to disk, process-then-discard, explicit consent). 
• Build the parent side as a dedicated React Native mobile app, not a web dashboard. 
• Evaluate the full mood -detection-to-recommendation pipeline end to end, not just each 
component in isolation. 
• Full system testing (unit, integration, user acceptance) across both student and parent sides. 
• Finish project documentation and the final report.

9. Conclusion and References 
At the mid -progress stage, EduEats's student -facing pipeline is fully built and verified: mood 
detection from webcam images, rule-based nutrient mapping, food recommendation from a real 
USDA-sourced dataset, and posture monitoring all work together end -to-end, backed by a live 
MySQL database and a tested React frontend, with the CNN reaching a real, honestly -reported 
61.4% test accuracy. The project is on track to finish on time; the main remaining work is the 
parent-facing side. Rather than proceeding with the originally planned phone -push-notification 
design after it was flagged as a privacy concern, this component is being deliberately 
redesigned as a dedicated mobile application with more careful data handling - a decision made 
in response to real review feedback, and the clear focus for the re mainder of the project 
timeline
